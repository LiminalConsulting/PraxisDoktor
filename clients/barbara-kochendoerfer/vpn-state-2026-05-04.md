## Warum Bordmittel-IKEv2 statt LANCOM-Client

Der LANCOM Trusted Access Client (NCP-OEM) hat **keine ARM64-Build**. Installer rollt sich beim Treiber-Setup automatisch zurück ("Aktion wird rückgängig gemacht" → "Assistent unterbrochen"). Ursache: kernel-mode NDIS-/FIPS-Treiber, der nur x86-64 signiert ist. Vendor bestätigt: kein Roadmap-Eintrag für ARM. x64-Emulation hilft nicht (Treiber emuliert nicht).

Lösung: **Windows-eigener IKEv2-Client** (nativ auf ARM64 verfügbar seit Win7).

### Antwort B: "Crypto-Proposals sind XYZ"
→ Schauen welche Suite das ist und passend setzen via `Set-VpnConnectionIPsecConfiguration`. Übersicht der Windows-IKEv2-Cmdlet-Werte:

| LANCOM-Vokabular | Windows-Cmdlet-Wert |
|---|---|
| AES-128 | `AES128` |
| AES-256 | `AES256` |
| AES-128-GCM | `GCMAES128` |
| AES-256-GCM | `GCMAES256` |
| SHA-1 | `SHA1` (für `IntegrityCheckMethod`) / `SHA196` (für `AuthenticationTransformConstants`) |
| SHA-256 | `SHA256` / `SHA256128` |
| SHA-384 | `SHA384` / kein direkter Auth-Transform-Wert (GCM nutzt Integrity stattdessen) |
| DH Group 2 (modp1024) | `Group2` / `PFS2` |
| DH Group 14 (modp2048) | `Group14` / `PFS2048` |
| DH Group 19 (ECP-256) | `ECP256` / `ECP256` |
| DH Group 20 (ECP-384) | `ECP384` / `ECP384` |

Befehl-Schema (Admin-PowerShell):
```powershell
Set-VpnConnectionIPsecConfiguration -ConnectionName "Praxis Kochendörfer" `
  -AuthenticationTransformConstants <X> -CipherTransformConstants <X> `
  -EncryptionMethod <X> -IntegrityCheckMethod <X> `
  -DHGroup <X> -PfsGroup <X> -Force
```
